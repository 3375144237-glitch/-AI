# 问题与报错日志

## 使用规则

- 开始新项目或在项目中创建新文件前，先阅读本日志；如果发现新坑或可靠的解决办法，及时补充。
- 记录可复用的问题、原因、处理方式和适用范围，删去重复和过时内容。
- 本日志及其他核心文档控制在 8000 字以内；达到 7200 字时立即蒸馏，保留结论和可复用步骤，压缩重复背景，并检查最终字数仍低于 8000 字。

## 可复用经验

### GitHub HTTPS 推送报 HTTP/2 错误

- 推送长时间无响应并报 `Error in the HTTP2 framing layer` 时，可用 `git -c http.version=HTTP/1.1 push` 单次重试，不改全局 Git 配置。推送后用 `git ls-remote` 核对远端分支的提交号。

### Figma 评论读取与设计验收

- Figma MCP 不提供评论读写能力；通过 `~/.codex/bin/figma-comments` 读取、发表或回复评论。
- 设计还原或 UI 验收前，先读取对应页面评论；链接包含 `node-id` 时，评论范围为该图层及其子图层。
- 对评论发表或回复之前，先让用户确认评论内容，因为协作者可见。
- 不要打印或写入 Figma 访问令牌。

### 设计稿与旧 Demo 不一致

- 现象：同一项目的设计稿与 Demo 出现品牌、文案或入口差异。
- 原因：Demo 可能保留旧版界面及模拟流程，不能自动代表本期最终需求。
- 处理：在 PRD 中分别记录截图可见内容、Demo 已演示能力和待确认差异；不要把原型注释或模拟结果直接当成已确认规则。
- 用户明确要求沿用原型文案时，先逐项列出对应产物的标题、表头、数据、状态和说明，再按原文校验。按设计系统重排不等于可以改写或合并不同口径的内容；截图截断处查对应 HTML 渲染内容。
- 原型写在页面里的接入提示和实现备注可能只是供团队核对，不进面向用户的稿。短表与统计条重复时逐行状态留在表内；相同 SKU 出现在不同视图代表不同记录，保留各自证据和真实合计。模拟提示集中在对应结果旁。
- 适用范围：同时参考设计稿和历史交互原型编写需求时。

### 从 Figma 原稿提炼设计规范

- 图层名称可能与实际文案不同，颜色也可能附带透明度。例如按钮层名为「提交」，可见文字为「知道了」；状态标签底色是 10% 色，不能按实色计算对比度。
- 处理：核对实际 `characters`、填充透明度及截图，再区分原稿实测值和建议值；状态色以合成后的前景和背景计算对比度。
- 建组件前先找定稿里的真实用例，按实际尺寸、排布、配色和字体验收。母版完成后，只在独立的业务行副本中验证实例链接、布局和相邻控件位置，并与定稿截图对照。
- 定稿默认只读。禁止为验收直接替换定稿实例；调整母版、变量、样式前检查定稿的直接及嵌套引用。会传递到定稿的变化使用独立库资产，无法确认影响范围时暂停。参见根目录 `AGENTS.md`。
- 输入框有三种已验证用例：名称字段是 32 px 高、白底、8 px 圆角；商品筛选搜索是 32 px 高、6 px 圆角；收藏夹搜索是 28 px 高、6 px 圆角。两种搜索框均复用原稿图标。复用原稿苹方图层并链接默认文案，可避开后台字体加载限制；改写文案仍需加载原字体。
- 售卖 AI 的 Input 错误描边和提示文字复用已确认的 `#FF6C3A`，不要套用旧规范中的 `#B42318`。原稿的红色必填星号是独立语义，保持原样。补状态前同时核对原稿取色和用户已确认的调整。
- 读取 Figma 搜索框的填充时检查 Paint 的 `visible`：商品筛选与收藏夹搜索虽记录了 `#F5F7FA`，原稿默认态实际关闭填充。原稿未画的状态要注明是补充，并验收描边变化是否影响文案坐标、文案是否适配场景。
- 核对下拉展开态时，先查整张定稿画板的同级浮层，按绝对坐标与截图匹配触发器；不能只查筛选行子层、图层名称或「全部渠道」文案。售卖 AI 定稿 `203:27615` 中，触发器 `203:28281` 有 1 px `#E5E5E5` 内描边，独立展开面板 `203:28417` 无描边、无搜索框；两层相距 4 px，浮层为白底、8 px 圆角、`0 4 24 0` 黑色 12% 阴影。
- 原稿和实例的字体属性、文案及坐标相同，旧文字缓存仍可能造成导出差异。用桌面插件仅在临时副本里改变并还原原稿文案，再导出比较；本次三种默认态在同一字体环境导出的 PNG 一致。保留原稿，清理临时副本。
- 搜索图标和文字层间距正确时，文字居中仍会拉大实际图文空隙；文字应左对齐，宽度变化时只改变截断位置。用长占位、短值和不同宽度导出核对。
- 2026-11-20 同页原稿复核：商品搜索默认占位沿用原稿的受限宽度、窄版截断和居中属性；已填值仍从左侧起排。验收时先固定复制行的原始宽度，再比较字体、图文位置和渲染；不要让 Fill 把三个样例都撑到同宽。
- 整行替换不能只验原始宽度。名称字段、商品筛选、收藏夹标题栏各做原始宽、窄版、宽版对照；核对相邻控件和标签的坐标。表单输入填充、商品筛选三等列、收藏夹搜索固定 200 并靠右。提示文案和控件共用一列，标签只与控件行居中。
- `Table / Cell` 双行实例覆写文案后再改宽，内部文字可能保留旧宽度，导致商品名截断或列起点错位。按最终列宽新建同一母版的实例，再覆写文案；读回两行文字的位置、宽度和母版链接，并看实际导出。报告排版先量定稿的区块间距，原型只提供业务内容。
- 同一自动布局里混用输入实例和普通图层，Fill 不一定等宽；用三个结构相同的列容器包住控件，容器与控件均 Fill，结果计数 Hug。复制嵌套实例若留下异常文字几何，从母版重新创建，再用桌面字体环境写入文案。

### 长图裁切为文档插图

- 现象：用 `sips --cropOffset` 传入负数时，裁图出现大片黑色空白。
- 原因：裁切偏移按原图左上角计算，负偏移超出图像边界。
- 处理：使用非负的纵向、横向起点坐标裁切；逐张预览裁图，并检查 Markdown 中的图片路径均存在。
- 适用范围：将长截图拆成 PRD 中的局部配图时。

### Figma 评论令牌无效

- 现象：`figma-comments` 读取评论时返回 401 `Invalid token`。
- 处理：确认令牌在 Figma 中有效且有目标文件权限；不要将令牌写入项目文件或终端日志。设计文件连接可用时可先核查文件结构，但评论约束仍需单独核对。
- 适用范围：使用个人访问令牌读取 Figma 评论时。

### 仓库的 Figma 节点链接失效

- 现象：文件仍可读，但文档里的旧画板节点返回「未找到」。处理：从用户给的页面入口只读列出画板，按名称、内容与尺寸找到对应稿，并打开截图交叉核对，再在新文档中引用已核验的节点。文件可以读取不代表评论也能读取，两者分别记录。

### Figma 字体与编辑环境不一致

- 现象：定稿使用苹方-简（`PingFang SC`）。macOS 能解析本机字体，Figma 桌面字体缓存也有记录，但官方远程 MCP 无法加载 Regular、Medium、Semibold，实例文案覆写会因字体缺失失败。
- 复测（2026-11-18）：重装后 macOS 仍可解析三个字重，但新装的用户字体中没有 `Semibold`（系统内置字体有）。刷新 Figma 文件后桌面端仍提示缺失苹方，官方远程 MCP 对三个字重的加载也均失败。
- 桌面处理已验证：用 Talk to Figma 扫描并按原字重选择替代字体图层，再在桌面端字体面板应用 `PingFang SC`。该插件的改字接口只改文案；应用字体后用插件读回，核对字重、字号和文案。此路径已验证 Regular、Medium、Bold。用户已确认新增附件标题可用 Bold 替代缺失的 Semibold；原定稿仍保留 Semibold。
- 仅改苹方文字填色时可直接用桌面插件，不必替换字体。桌面回读可能先于云端同步；等云端也读到新色值再验收截图。
- 处理：分别验证本机、桌面 Figma 和远程 MCP。保留原稿苹方图层与组件实例，新建或改写正文须在能加载苹方的环境完成，不默认使用替代字体。仅需特殊强调的数字使用 `Poetsen One`（官方 MCP 识别为 `PoetsenOne Regular`，已验证可加载）。
- 不操作用户窗口时，可通过 Figma 后台复用现有苹方文字图层，再用已连接的 Talk to Figma 改写文案。复制到另一宽度后，检查导出中的实际断行；宽度属性正确仍可能沿用旧断行，可在桌面字体环境重新写入文字以刷新布局。
- 远程给苹方图层写入字符后，节点可能读回新文案，但截图仍显示旧字形或空白；必须看真实导出。桌面插件只返回加入频道成功时，也需用读取或导出验证实际连通。
- 批量改既有苹方字重或行高时，用桌面插件按 ID 选择文字层，再在 Figma 字体面板编辑。保留文字层 ID 和组件属性引用；面板有时读到上次选择的字重，最终以逐层读回和桌面导出为准。
- 桌面无法为苹方 Semibold 创建样式时，可把定稿文字复制到独立样例，按比例缩放保留原字重和文案。验收字号、行高和实际导出；复制文字图层不等于创建了可复用的文字样式。
- 远程读回的字重是图层配置。新稿和定稿都报 `hasMissingFont` 时，不能据此断定某一稿在用户桌面发生字体回退；在同一字体环境、相同缩放下对照实际渲染。
- 同样显示苹方 Medium 的图层也可能读出不同数值字重。交接权限盘点的 AI 稿主模块标题读出 400，用户副本为 500，导出也更粗。验收同时核对 `fontWeight`、样式名和实际渲染。
- 适用范围：跨设备或远程环境编辑现有 Figma 文件时。

### 复用 Figma 实例时的缩放偏移

- 现象：把原稿 700px 输入组件实例先缩到 402px，再放回 700px 后，实例内的提示文字仍保持错误宽度和负坐标，溢出边框。
- 原因：实例缩放可能保留内部覆写或重新计算子层约束，外框尺寸恢复不代表内部几何也恢复。
- 处理：先按目标宽度新建原稿实例；全宽画板直接使用未缩放的 700px 实例。每次缩放后检查内部文字坐标并截图。
- 适用范围：跨画板复用响应式 Figma 组件时。

### 描边与形状混用导致高度漂移

- 现象：标题栏和分屏导航在使用额外 1px 分隔形状时，与原稿描边的高度和内容起点不一致。
- 处理：先检查原节点的 `strokeAlign` 和单侧描边设置；使用原生描边并删除额外分隔形状，再核对自动布局子层的 `y` 和高度。
- 适用范围：按已有 UI 规范补页或复用标题栏、导航栏时。

### 定稿外描边被相邻内容挡住

- 现象：自动布局的标题栏已有 1px 底部外描边，但下一兄弟层的白色填充盖住描边，面板属性和导出截图不一致。
- 处理：保留原有外描边与容器尺寸，调整父自动布局的画布叠放顺序；浮层单独放在顶层并保留绝对定位。验收时同时检查节点属性与导出图像的边界像素。

## 待补充

### 用定稿资产时按子层核验

- 外框尺寸一致不能代表复用结果一致；检查父自动布局间距、文字字体和行高、可见状态及按钮子层。已定稿的既有资产保留原属性（含附件说明字号 13px），新绘制区域才沿用偶数规格。字重加载失败要明确列为差异，不能以外框一致代替。

### 列表跨状态的字段口径

- 同一商品可同时库存异常和同步失败。库存值及其警示留在库存列，同步列保留同步状态或失败数。修改表格母版后，分别对照全量、筛选、空态及详情背景中的实例，核对结果数、字段含义与列对齐。

### 组件盘点按实际组合和引用核验

- 业务画板有样式、图层叫组件名或属性列出了状态，都不足以证明状态齐全。查实际变体和嵌套链接，再把缺项并回已有预览：Table 保留 352 px 对照并展示其他宽度的代表状态；查询表单补入 Input 的原稿对照，复用 Input、Select 与 Button。只有独立复用需求才新增组件母版。
- 远程环境不能覆写苹方时，切换既有 Button 实例的变体仍可保留已经覆写的动作名。例如复制「查询」实例再切到 `loading`，属性值继续是「查询」，图面按母版显示加载图标。补建前后分别记录定稿图层、可见内容、尺寸和实例链接的指纹，检查母版调整是否联动定稿。

### 自动布局要实际验证删减回流

- 画板上出现自动布局标记，并不代表固定尺寸或占位层已经解决。预览、搜索框和抽屉正文用填充；附件组、渠道列表和操作栏随内容收缩。边线如只用于区分固定操作区，排除在布局高度计算之外。验收时在临时副本删除真实兄弟节点，核对宽高变化，再清理副本。
- 合并组件预览时移动原有对照画板进统一预览，保留节点链接与实例，逐组核对原稿行尺寸。页面按每组母版与预览的较高一边计算下一组位置；说明改字后重新检查间距、边界相交和导出裁切。
- 指标示例加标题后，桌面画布可能按插入标题前的高度裁掉底排，云端导出仍完整。对照用户截图，检查实例到预览外框的裁切链；示例容器关闭裁切、按内容收缩并留 8 px 底距，保留母版与实例尺寸。
- 测试插槽网格时只改实例宽度，保留原自动布局轴的设置；重设交叉轴会把垂直母版改成横向随内容收缩，使网格看似不换行。核对实际插槽宽度、每排列数和总实例数。
- 表格无数据时不沿用有数据的固定宽列。普通列设填充；分屏用随实例变宽的表头容器预留操作列，验收加宽、缩窄时的接缝和文字。嵌套单元格用插槽保留原文，内边距留在母版根层；移进插槽会改变参与自动布局的宽度，可能让同一行其他列偏移。

### 分屏验收按使用任务走一遍

- 574 px 报告先按标题职责和父级分组对照同场景定稿：总标题 20/30 Semibold，正文一级标题 16/16 Semibold，正文大组之间 32 px；定稿的 24 px 是外层段距，不能直接平铺给所有小节。紧凑商品明细另有 14/14 Semibold、标题到表格 12 px、说明标题到正文 8 px 的范例。通用 16 Medium 只用于没有更匹配定稿时。
- 多表格报告不在模块之间加横线，以免和表格边线一起显得琐碎。交接权限盘点用 32 px 留白区分模块，标题、口径和表格按组内小间距排列。提醒的标题和说明放进同一浅灰提示块；验收时保留表格自身边线。
- 先按语义归组，再以有效行宽的一半判断标题能否并排放附属内容。标题即使未过半，也要检查两边加间距是否放得下。交接权限盘点的库存标题实测 215 px，在 574 px 宽时可与覆盖范围同排，换成 374 px 宽时范围下移。
- 依次检查小窗里能否定位异常、固定产物后是否按可用宽度重排、全屏能否跨列对比、明细是否说明处理完什么再重试。自动布局的 Fill/Hug 只验证几何变化，不能代替窄版的信息取舍。列表列线用于追踪跨列对应，短列表优先用对齐和留白；视觉强调给用户正在选择的视图与下一步动作。
- 窄栏页签先用显示宽度求和，再加组距，最后看导出。售卖 AI 的四项共宽 323 px，组距 32 时总宽 419，改用已有 16 px 变量后总宽 371，可放入 374 px。状态对照板也先计算实例宽度、组距、容器内边距和描边，再调整画板，避免压缩业务表格列宽。
- 只改右侧报告且要保留左侧位置时，复制原画板，在副本锁住侧栏和会话的原始高度，再按右侧内容增高画板。下方只延伸底色与分隔线。导出后裁取原高度内的左侧区域，与定稿逐像素比较。

### Figma 变体合并与文字宽度

- 现象：合并同名文字属性的变体后，状态颜色正确但部分标签仍显示第一个变体的文案。窄版实例里按固定文字宽度缩放后，还可能出现行高溢出。
- 处理：语义由变体决定的标签直接保留各变体的文字；状态不同的实例读回实际文案。文件说明在母版使用填充宽度和自动文本高度，窄版用新的原生实例验证换行及行高。
- 在已有组件集内克隆变体，图标 Slot 可能变成普通 Frame，文案与显隐属性引用也会丢失。复制原母版子层的 `componentPropertyReferences`，包括 `slotContentId`，实例内即可恢复 Slot。切换状态后核对实例的自定义文案、图标和加载宽度。

### Figma 颜色变量与透明度

- 颜色变量绑定到填充或描边时，单独写入 Paint 的 `opacity` 会被变量的 Alpha 覆盖。禁用态如果要求整颗组件一起变淡，应沿用默认配色并设置组件根节点 `opacity`；按状态区分的背景色则单独使用颜色变量。验收时读回透明度并检查实例渲染。
- Figma 布局示意同样直接绑定语义颜色，不能手填近似色。云端无法加载苹方时，可应用现有苹方文字样式；小字缩放后恢复原文本框宽度。读回字族、字重、字号与链接，再看导出。云端仍可能报缺字体，不能据此确认实际渲染所用字体。

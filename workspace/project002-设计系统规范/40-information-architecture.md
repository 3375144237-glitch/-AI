# 04 Information Architecture｜信息架构

[Figma 信息层级](https://www.figma.com/design/7dVg1Mgu2O9Gnsg1mwrGRf?node-id=174-4244)

| 阅读顺序 | 应回答的问题 | 放在这一层的信息 |
| --- | --- | --- |
| 1. 对象与范围 | 正在看什么？ | 产物名称、查询范围、筛选条件、数据时点（只有来源提供时才写）。 |
| 2. 结论与风险 | 先看哪里？ | 有口径的总量与异常数、库存风险、同步失败。 |
| 3. 记录与定位 | 哪些记录受影响？ | 商品 / SKU、可用库存、同步结果、独立状态及明细入口。 |
| 4. 明细与恢复 | 接下来怎么做？ | 失败原因、影响范围、可执行动作及重试结果。 |

## 内容规则

- 标题使用业务对象，如「商品清单」「库存异常」；状态词不充当标题。同级标题字号、字重一致。
- 用留白、对齐、细线区分模块；同一时间只突出一个主要风险或下一步动作。
- 库存异常放库存字段或对应标签；同步状态和失败数留在同步字段。一个商品可同时有两类风险。
- 真实零值显示 `0`；未提供或不适用显示「—」；无匹配用结果区域反馈，不伪造空行。
- 固定分屏优先保留对象、范围、风险与明细；长渠道列表和辅助字段允许进详情。全屏保持同样顺序，展开列信息。
- 权限不足时不显示受限的详情、数量或推断结论；有授权路径才给申请入口。

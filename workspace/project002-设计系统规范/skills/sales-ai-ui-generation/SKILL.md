# 售卖 AI｜分屏产物 UI 生成

用此技能把聊天请求变成右侧分屏里的可读、可核对产物。先确定用户要看什么、比较什么或做什么，再决定呈现方式。简单问答直接在聊天中回答；涉及阅读、对比或操作时再生成分屏。

## 1. 给每种来源定职责

| 来源 | 用来决定什么 |
| --- | --- |
| 用户本次指令 | 任务、修改范围、是否保留原文及交付位置。后续确认的规则覆盖同一处早期做法。 |
| 产品实际数据、状态和权限 | 可展示的对象、值、范围与操作。真实能力以产品为准。 |
| 同场景 Figma 定稿、组件库 | 信息层级、字体、颜色、间距、边框及交互。按标题和组件的实际职责找对照，优先复用真实实例与变量。 |
| 原型截图、HTML | 提取业务内容、顺序、字段和交互意图。指定只参考右侧时仅读相关区域，不拿原型的外观覆盖定稿。 |

在本仓库内，先读 `workspace/问题与报错日志.md`。详细口径以仓库根目录下 `workspace/project002-设计系统规范/` 为准：先读 `50-ai-generation-rules.md`，需要完整页面、组件或变量时从 `00-design-delivery.md` 找对应样例。拿不到同场景定稿时，用最接近的已确认样例和组件，差异标为「设计补充」或「待核」。

定稿默认只读。写 Figma 前确认用户已明确授权目标文件、页面、区域和改动范围；只在授权的草稿或副本内执行。只改分屏时，保留左侧、聊天区、分屏顶部栏与宿主控件。授权新建并放到指定稿件下方时，在空白处放独立画板，不移动原稿。不要通过母版、共享样式或变量间接改动定稿。按项目规则先读相应 Figma 评论；无法读取时记为待核。用户要求不抢屏幕时走后台工具，不切页、不改变选择或视口。

## 2. 选择产物，筛选用户文案

| 类型 | 内容顺序 |
| --- | --- |
| 分屏网页 | 标题、范围与关键指标 → 按需提供可用的视图或筛选 → 结果 → 明细或下一步。 |
| 报告 | 标题、范围、快照或状态 → 关键结论 → 数据依据与明细 → 按需放影响、建议或真实附件。 |
| 表格预览 | 表名和范围 → 按需放筛选和结果数 → 表头、表身 → 可用的分页或明细。默认只读。 |

1. **先筛受众。** 展示对象、范围、结果、限制、风险和可用动作；把研发接入、实现备注、占位演示和验收说明留在团队记录。样例数据、模拟权限或快照时效会影响用户判断，须在对应内容旁明确标明。
2. **再去重。** 同一模块里对象、范围、口径和用途都相同的信息只保留一次：总数留摘要，字段留所属范围，逐条状态留表格行，整表共用说明留在表旁。上级标题已交代表格用途和范围时，可直接接表；如果结果仍是模拟的，须在表旁保留一次说明，避免把「需申请」读成正式核验结果。保留有独立用途的跨视图汇总、每条证据和关键警示；同一 SKU 在可售和库存视图属于不同记录。
3. **保留来源。** 用户要求沿用原文时，保留项使用来源原文，不自编标签、数值和结论；精简混有内部说明的句子时，只摘取原文中的用户信息，并核对含义。保留原业务顺序，除非用户授权调整。区分真实的 `0`、缺失、无匹配、异常和无权限；无真实数据时不填看似真实的结果。只展示真实可用、已授权的操作。

## 3. 先做内容分组，再排版

1. **按同一个阅读任务成组。** 标题、渠道范围、行数和对应表格是一组；快照时间和更新说明属于报告头；异常合计属于异常摘要，模拟授权说明属于权限表。标题能放下别的内容也不能跨组拼排。键值列表分别对齐字段列和值列，按内容宽度定列，不固定各占一半。表格保留原有组件和列关系。
2. **拉开主模块，收紧组内。** 用标题、对齐和留白划分模块。相同间距优先设置在同级模块的父级自动布局上；模块内边距用于内容与容器边缘的距离。574 px 报告可参考大组 32 px、标题到所属内容 8–16 px，以同场景定稿实测为准。多表格报告的模块之间不加横线，保留表格自身的外框和行线。内容缩短后让布局自然回流，不留空容器。
3. **按行高判断上下间距。** 同组上下两条文案的行高都等于各自字号时，优先用 6 px，仍显得贴近时可放到 8 px；任一条为 1.5 倍行高就沿用该场景的正常间距。组内仍小于组间；保留既有组件的行高。
4. **按职责复用字体。** 让模块标题、表内主名称和关键结果容易扫到。574 px 报告样例使用苹方 20 px / 30 px Semibold 总标题、16 px / 16 px Semibold 一级区块；紧凑商品明细的同类标题用 14 px / 14 px Semibold。找不到更贴近的定稿时，才用通用的 16 px Medium。Figma 中同样显示 Medium 的图层也可能分别读出 400 和 500；核对数值字重与同缩放导出，不能仅凭样式名判定一致，也不能仅凭远端缺字判定桌面发生回退。
5. **按文字职责选色。** 快照时间、覆盖范围和备注等辅助、次要文案优先 `#999999`；需要更高对比度时按场景规范选色。表头、关键数据、操作和状态保留各自语义色。
6. **说明区使用次级层级。** 提醒、变更影响和口径说明可用比主模块小的标题。服务于同一阅读目的的说明可放进同一个已有的浅灰提示块；需要区分内部小节时，才按同场景样例用细线。卡内小节的分隔不适用于主模块之间。「交接权限盘点」副本的 12 px 提示标题和卡内细线是案例参考。

### 标题同行判定

令 `W` 为标题行扣除内边距后的可用宽度，`T` 为实际字体、字重、字号下标题不截断的自然宽度，`R` 为同组附属内容的完整宽度，`G` 为所需间距。

- 仅当 `T ≤ W / 2` 且 `T + G + R ≤ W` 时，才允许相关状态、范围、计数或短说明放到右侧。状态标签可就近跟标题；平行表格的范围和行数可在同一右边界对齐。
- 报告身份与时效可同行：标题和状态标签在左，单个快照时间可在最右，更新说明留在下方。算是否放得下时计入标签和两侧间距。时间含义明确才省略前缀；存在多个时间口径或明确要求沿用原文时，保留必要标签。
- 标题超过半行、需要换行，或附属内容放不下时，标题独占一行，附属内容回到其下方。不要靠缩字号、改字距或截断制造同排。面板宽度、内边距或文案改变时重算。
- 校验例：库存标题 215 px，范围和行数 170 px，组距 12 px；在有效宽 574 px 时可同排，在 374 px 时范围下移。提醒标题 288 px，提示块扣除左右内距后只剩 550 px，288 大于 275，说明留在标题下方。

## 4. 用最终渲染验收

- 按实际内容宽度检查；374、574、1034 px 是售卖 AI 的参考档，不是浏览器断点。窄版保住关键结果与完整标题，宽表只在表格内部滚动或由宿主展开。切换宽度不得改变数据口径、筛选和选中项。
- 对照导出图或实际预览：第一眼能看到模块起点和内容归属；同排标题通过两个宽度判断；颜色、数值字重、行高和组件实例与参考一致。精简后仍能看出时间口径、权限结果是否为模拟，文案无重叠、裁切、内部说明或无意义复述。
- 改已有草稿时，核对改前改后：原文和关键数据符合约定，组件链接、表格自身边线与修改范围外的画面保持原样。只改分屏时可用同尺寸截图对照左侧和顶部栏。
- 交付只报告产物链接、改动范围、采用的主要规则及待核差异。设计依据和验收记录不进入用户界面。
